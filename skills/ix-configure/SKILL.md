# NEC IX 設定投入

`ix-ssh --config` / `--config-file` で設定を投入する。
投入前に対象・具体的な設定行・永続化の有無を示して確認する。
同じ対象・設定行・永続化の扱いについて既に承認がある場合は再確認しない。単なる案の作成依頼では投入しない。

## 接続先と実行条件

ユーザーの依頼と会話で確定した対象を使う。インベントリの機器は毎回
`--device <機器名>`（短縮 `-d`）で明示する。
対象が未確定なら `ix-ssh --list` で候補を示して尋ねる。機器名を推測しない。
一覧は機器に接続せず、インベントリの実際の場所、接続先、踏み台、`model`、`note` を表示する。
通常のインベントリは `~/.ix-toolkit/devices.json`。資格情報を含むファイル全体を表示する必要はない。
インベントリに無い対象が明示されていれば `--host <IP/ホスト名> --user <ユーザー>` も使える。
SSH のエイリアスと `ProxyJump` は `ix-ssh` が解決する。

`ix-ssh` は PATH のコマンドとして呼ぶ。見つからなければ README のインストール手順
（クローン → `uv tool install -e <クローン>`）を案内する。認証不足ならエラーの不足項目を伝え、
無人実行で `--ask-password` を付けない。

通常は `enable-config` を使う。他ユーザーが config モードを使用中なら停止し、
ユーザーが対象機器への強制取得を明示した場合だけ `--force-config` を付ける。
既にある指示を再確認しない。強制取得は `svintr-config` を使い、両系列とも Administrator 権限が必要で、
他ユーザーをオペレーション／EXEC モードへ戻す。使用中エラーだけを理由に切り替えない。

## 投入案を作る

`ix-ssh --list` で対象の接続先と `note` を照合する。会話で確定した機器も使える。
インベントリに無い機器は、明示された `--host` / `--user` を確認対象にする。

系列はインベントリの `model` → 会話 → ユーザーへの質問の順で決める。
`IX2…` / `IX3…` は `ix`、`IX-R…` / `IX-V…` は `ix-r`。
`model` が無いことだけを理由に止めない。依頼の範囲で取得した `show version` も判断材料になる。

`ix-show` で関連する現在の設定を読み、インターフェースを変更するなら `show interfaces` で名前を確かめる。
要求と現在の状態の差から、必要な設定行を組み立てる。
綴り・引数・実行モード・権限・`no` 形が不確かなら、系列と機種を添えて `ix-manual` を引く。
`no` 形を単純な接頭辞の追加だけで作らない。再起動要否や併用不可など、適用に関係する制約も確認する。

IX-R/IX-V への投入では `ix-manual` の系列間対応表 `diff.tsv` と照合する。
詳細は同 skill の [系列間差分の読み方](../ix-manual/references/differences.md) を参照する。
改名は構文、モード移動はブロック位置、廃止・非対応は代替案、範囲・パラメータ変更は値を確認する。
索引の集合差 `setdiff` だけで非対応と断定せず、差分表に無いことも互換性の根拠にしない。

## 実行前に提示するもの

- 対象機器と解決した接続先、系列・機種とその判断材料。
- 投入する設定行（サブモードへの移行・復帰を含む）と変更の目的。
- 該当する系列差分、通信断や再起動など変更に伴う影響。
- バックアップ先と永続化の有無。永続化は running-config 全体を保存する。

未承認なら、この具体的な案への確認を取る。承認後に対象・設定行・永続化の扱いを変える場合は、
変更分を示して承認を得てから実行する。
複数機器では対象ごとの差分を明確にし、承認された範囲で1台ずつ結果を確認して進む。

## 投入する

変更前の running-config は `ix-backup` で退避しておくことを推奨する。
`--backup` を同時指定すると、バックアップの取得・書き込みが成功してから設定を投入する。
既に退避してある場合は、その保存先を記録して使える。

```bash
ix-ssh -d <機器名> --backup --config "<確認済みの設定行>"
ix-ssh -d <機器名> --backup --config-file "<確認済みの設定ファイル>"
```

短い設定は `--config` を行ごとに繰り返す。ファイルは UTF-8、1行1コマンドで、空行と
`#` 始まりの行は無視される。`--config` と `--config-file` の併用時は、前者の全行の後にファイルの行が続く。

`ix-ssh` が config モードへの入退出を行う。設定するサブモードへの移行は設定行に含め、
サブモードからグローバルへ戻すには `configure` を使う。
多くの設定は即時反映され、トランザクションや自動ロールバックは無い。

**1回の実行順は show → backup → config → save。**
同時指定した show は変更前の状態を返す。投入後の確認は別の呼び出しで行う。
永続化まで承認されていれば `--save` を付けられるが、その場合は投入後の確認より先に保存される。
動作確認後の保存が必要なら `--save` を付けず、確認後に `ix-save` を使う。

## 結果を確かめる

終了コードと診断本文、`# target: ...` と承認対象の一致を確認する。
`# target` は接続前の解決結果なので、この表示だけで接続・投入成功としない。
`%` で始まる正常通知もあるため、記号だけで失敗と判定しない。
再起動が必要との警告は未反映の変更として伝え、再起動を自動実行しない。

設定エラーや切断では先行する行だけが反映されている可能性がある。
同じ設定一式の再投入・保存・巻き戻しへ自動で進まず、`ix-show` で現在の状態を読み直す。
投入済みと未確認の部分を示し、必要な修正案を作る。

成功時も、別の `ix-show` 呼び出しで関連する設定と動作を確認する。
対象、適用結果、バックアップ先、保存済みか未保存か、残る作業を報告する。
未保存ならその旨を伝え、永続化が依頼されていれば `ix-save` まで進む。
