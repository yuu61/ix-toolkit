# NEC IX マニュアル参照

`manualbook` で変換したローカルのマニュアルを検索する。読み取り専用で、機器には接続しない。

## 系列・機種と冊子を選ぶ

系列はインベントリの `model` → 会話 → ユーザーへの質問の順で決める。
インベントリの既知の情報、または機器に接続しない `ix-ssh --list` の表示を使える。
通常のインベントリは `~/.ix-toolkit/devices.json` で、実際に使う場所は一覧の先頭に出る。
資格情報を含むファイル全体を表示する必要はない。

| 系列 | 機種の目安 |
|---|---|
| `ix` | IX2000/IX3000（`IX2…` / `IX3…`） |
| `ix-r` | IX-R/IX-V（`IX-R…` / `IX-V…`） |

`model` はヒントであり、無くても会話から判断する。既に取得された `show version` も使える。
この調査のために接続して機種を調べない。比較の依頼なら両系列を引き、1つに絞る質問は不要。
諸元値は系列だけでなく機種に依存する。機種が不明なら尋ねるか、機種ごとに値を示す。

| 調べること | 冊子 | 索引 |
|---|---|---|
| 綴り、入力形式、引数、デフォルト、実行モード、権限 | `crm`（コマンドリファレンス） | `commands.tsv` |
| 仕組み、構成、諸元値・上限、設定例 | `fd`（機能説明書） | `sections.tsv` |
| 系列間の改名・廃止・モードや条件の変更 | 両系列と対応表 | `ix-r/diff.tsv` |

必要な冊子から読み、両方が関係するときだけ併用する。
インターフェース名は機種名やマニュアルの例から実機の名前として確定しない。
実機へ適用する名前は、接続を伴う作業で ix-show の `show interfaces` と照合する。

## マニュアルを見つける

次の順に存在する場所を探す。最初に見つかったルートを `<manuals>` とする。

1. 環境変数 `IX_MANUALS`（`$IX_MANUALS`）のパス
2. `~/.ix-toolkit/manuals/`
3. `~/.claude/ix-manuals/`

本文と索引は `<manuals>/<系列>/<冊子>/` にある。
必要な冊子の `README.md` で系列・版・出典を確認し、その冊子の索引を探す。
版は固定値として扱わず、読んだ冊子の値を回答に使う。別ルートの版を黙って混ぜない。

必要な資料が無ければ不足する系列・冊子と場所を伝える。手元の資料で答えられる部分は示し、
不足部分を記憶で補わない。生成方法は ix-toolkit の README を案内する。
マニュアルの取得・再変換をこの参照作業から自動で始めない。

## 索引から本文へ進む

索引はタブ区切り。検索・ファイルの部分読みは利用可能なツールやシェルで行う。

| 索引 | 列 |
|---|---|
| `commands.tsv` | `command / entry / file / line / source` |
| `sections.tsv` | `section / title / file / line / source` |

コマンドは `command` 列、機能は `title` 列を中心に探す。節番号は系列・版によって異なる。
例えば検索コマンドが使える環境なら、次のように候補を探せる。

```bash
rg -n -F "ngn ip enable" "<manuals>/<系列>/crm/commands.tsv"
rg -n -F "VLAN" "<manuals>/<系列>/fd/sections.tsv"
```

検索結果に付く行番号は索引内の位置。本文を開くときは **TSV の `line` 列**を使う。
候補が複数あれば、依頼の目的・実行モード・パラメータで絞る。意味の異なる候補が残るときだけ尋ねる。

`file` は冊子ディレクトリからの相対パス、`line` は本文の見出し行番号（1始まり）。
crm は30行程度、fd は60行程度から読み始め、該当項目の終わりまで必要に応じて広げる。
固定の行数でノートや脚注を切り捨てず、無関係な節全体の読み込みは避ける。
crm では次のコマンドの `##` 見出しが項目の境界になる。

crm の項目では入力形式（`no` 形を含む）、パラメータ、説明、デフォルト値、実行モード、
ユーザー権限、入力例、ノートを確認する。ノートの再起動要否や併用制約を落とさない。
索引に無ければ綴りの部分一致や日本語の機能名で対象冊子の本文を検索する。
それでも見つからなければ「参照した版に記載を見つけられない」と伝え、機能の非対応とは区別する。

## 必要な場合だけ読む詳細

- 表・機種別の上限・図や経路を答えるときは [表・諸元・図の読み方](references/tables-and-figures.md)。
  脚注と機種列を照合し、図の向きや包含関係は画像で確認する。
- 移行・改名・廃止や IX-R/IX-V の投入案を照合するときは [系列間差分の読み方](references/differences.md)。
  差分の種類と根拠の確度を分け、必要なら両系列の本文を読む。

## 根拠を付けて答える

依頼への答えを先に示し、系列・参照した版と出典を添える。機種依存の値には機種も付ける。
構文の質問には該当する入力形式と実行モード・権限・関係する制約を示す。
上限の質問には値・条件・脚注を示す。無関係な項目を毎回定型で列挙する必要はない。

出典の位置は索引の `source` 列と本文の出典リンクで確かめる。

- PDF の `pNNN` は物理ページ。版面の章別ページ番号とは異なり、PDF の `#page=NNN` に使える。
- Web は `cli/…html#…` のページとアンカー。冊子の `README.md` にある基底 URL を基に辿る。
- ローカル本文・図の相対リンクは、そのリンクを含むファイルのディレクトリから解決する。

実機の版と参照版が違うと分かっていれば、その適用範囲を明示する。
資料本文・変換結果・画像は手元での参照用であり、リポジトリへ追加したり外部に丸ごと配布したりしない。
