# NEC IX マニュアル参照

**読み取り専用。機器には一切接続しない。**

`manualbook` で Markdown に変換したマニュアルを検索する。**系列が 2 つ、冊子が 2 種類**あり、
どれを引くかで答えが変わる。

| 系列 | 機種 | 元資料 |
|---|---|---|
| `ix` | IX2000/IX3000（IX2106 / IX2107 / IX2207 / IX2215 / IX2235 / IX2310 / IX3315） | PDF（Ver 10.11） |
| `ix-r` | IX-R/IX-V（IX-R2510 / IX-R2520 / IX-R2530 / IX-R2610 / IX-V100） | Web（Ver 1.5a） |

| 冊子 | ディレクトリ | 索引 | 引くもの |
|---|---|---|---|
| コマンドリファレンス | `crm/` | `commands.tsv` | コマンドの綴り・入力形式・パラメータ・実行モード・権限 |
| 機能説明書 | `fd/` | `sections.tsv` | 機能の仕組み・構成・**諸元値（上限）**・設定例 |

**「このコマンドはどう書くか」は crm、「この機能はどう動くか / いくつまで設定できるか」は fd。**
両方に関わるとき（例: VLAN を設定したい）は、fd で上限と構成を確かめてから crm で綴りを取る。

## 系列を決めてから引く

**無印と IX-R はコマンドが違う。** 同じ名前で実行モードが違うもの（`http-server ip enable` は
無印ではグローバル、IX-R ではインタフェース）、名前が変わったもの（`show logging` → `show syslog`）、
片方にしか無いもの（マルチキャストは IX-R に無い）がある。系列を取り違えると、正しい綴りを
引いたつもりで通らない設定を返す。

系列は次の順で決める。

1. **インベントリの `model`。** `~/.ix-toolkit/devices.json` の任意項目で、`ix-ssh --list` の
   `model=IX2215` と、機器へ接続したときの標準エラー `# target: ... model IX2215` に出る。
   `IX-R…` / `IX-V…` なら `ix-r`、`IX2…` / `IX3…` なら `ix`。
2. **会話の文脈。** ユーザーが機種を言っている、直前に `show version` の出力がある、など。
3. **どちらも無ければユーザーに聞く。** このスキルは機器に接続しないので自分では確かめられない。
   接続する skill（`ix-show`）で `show version` を実行してもらってもよい。

`model` は**ヒントであってゲートではない**。無い・知らない値なら止まらず、2 → 3 で決める。
決めたら、回答に「IX-R 1.5a のマニュアルでは」のように**系列と版を添える**。

## マニュアルの置き場所

次の順に探し、最初に見つかったものを使う。以下ではその場所を `<manuals>` と書く。

1. 環境変数 `$IX_MANUALS`
2. `~/.ix-toolkit/manuals/`
3. `~/.claude/ix-manuals/`

その下が `<系列>/<冊子>/`。

```
<manuals>/ix/crm/                   <manuals>/ix-r/crm/
├── commands.tsv                    ├── commands.tsv
├── index.md                        ├── index.md
├── README.md      ← 系列・版・出典  └── ch21-リモートアクセス編/AAA.md
└── ch03-インタフェース編/NGN.md
<manuals>/ix/fd/                    <manuals>/ix-r/fd/
├── sections.tsv                    ├── sections.tsv
├── figures/p1057.png ← 任意         ├── figures/1_loop-guard.svg ← 図はここ
└── ch02-ルータの設定/VLAN の設定.md  └── ch02-ルータの設定/VLANの設定.md
                                    <manuals>/ix-r/diff.tsv  ← 系列間の対応表（後述）
```

まず `<manuals>/*/*/*.tsv` を一覧してどの系列・冊子があるか確かめ、必要なものが無ければ
**その旨をユーザーに伝えて止まる**（記憶からコマンドや諸元値を答えない）。
各冊子の `README.md` に系列・版・取得日が書いてある。

未変換なら [ix-toolkit](https://github.com/yuu61/ix-toolkit) の `manualbook` で生成する。
マニュアル本文は著作物なのでリポジトリには含まれておらず、各自の手元で変換する（手順は README）。

## 引き方（必ずこの順序で）

> 以下の `Grep:` / `Read:` は**やること**の指定であって、ツール名の指定ではない。専用の検索・
> 読み取りツールを持つエージェントはそれを使い（Claude Code の `Grep` / `Read` など）、無ければ
> シェルで同じことをする（検索は `rg` / `grep` / `Select-String`、指定行からの部分読みは
> `sed -n '<line>,+30p' <file>`）。画像は画像として開ける手段（`Read` / `view_image` など）で開く。

### 1. commands.tsv を引く

`commands.tsv` は `command / entry / file / line / source` のタブ区切り。
1 行 1 コマンドで、コマンド名がそのまま先頭列にある。

```
Grep: pattern="^ngn ip enable\t" path="<manuals>/<系列>/crm/commands.tsv"
```

綴りが不確かなときは部分一致で候補を出す（`ngn.*history`, `^ipsec ` など）。
**候補が複数あれば、推測せずに一覧を提示してユーザーに選ばせる。**

### 2. 本文を読む

`commands.tsv` の `file` 列と `line` 列が該当項目の見出し行を直接指す。
**その行から 30 行だけ読む（ファイル全体を開かない）。** 節ファイルは最大 60KB あり、
丸ごと開くと 1 コマンドを引くために 1 冊分の節を読むことになる。

```
Read: file_path="<manuals>/<系列>/crm/<file>" offset=<line> limit=30
```

`limit=30` で足りることがほとんどだが、`ノート` の途中で切れていたら
`offset` はそのままに `limit` を増やす。次の `## ` が現れたらそこが次の項目。

項目は必ずこの構成になっている（見出し語は両系列とも同じ綴りに揃えてある）:

- **入力形式** — コマンドの構文（`no` 形を含む）
- **パラメータ** — 引数の意味と範囲・書式
- **説明** — 何をするコマンドか
- **デフォルト値**
- **実行モード** — グローバルコンフィグ / インタフェースコンフィグ 等
- **ユーザー権限** — Administrator / Operator / Monitor
- **入力例**
- **ノート** — 制約・注意（再起動要否など重要な情報が入る）

### 3. 見つからないとき

コマンド名で当たらなければ、本文を日本語で全文検索する。

```
Grep: pattern="ヒストリ" path="<manuals>/<系列>/crm" glob="*.md" output_mode="content"
```

それでも無ければ「このマニュアルには記載が無い」と答える。
**記憶や類推でコマンドを作らない。** IX のコマンドは系列・機種・バージョンで異なる。

無印にあって IX-R に無いとき（またはその逆）は、**もう片方の系列にあるか**と
`diff.tsv`（後述）を見る。廃止・改名されたコマンドなら置き換え先が分かる。

## 機能説明書 (fd) の引き方

### 1. sections.tsv を引く

`section / title / file / line / source` のタブ区切り。`section` は節番号（`2.7.2`）、
`title` は見出し語。**見出し語を部分一致で探すのが基本。**

```
Grep: pattern="VLAN" path="<manuals>/<系列>/fd/sections.tsv"
```

節番号が分かっているなら `^2\.7\.2\t` で直接引く。節番号は系列ごとに違う。

### 2. 本文を読む

`file` と `line` が見出し行を指す。**その行から必要な分だけ読む（ファイル全体を開かない）。**
解説書の 1 節はコマンド項目より長いので、60 行から始めて足りなければ増やす。

### 3. 表の読み方 — 2 つの形がある

表は元資料で形が違う。**どちらかは見れば分かる。**

**Markdown の表（`| … |` の行）** — Web 由来（IX-R）。**値は見出し行の列名で引く。**
諸元表なら見出し行が `| 項目 | IX-R2530 仕様 | IX-R2520 仕様 | … | default | 制限値 |` で、
機種名の列を取る。元の表でセルが結合されていた箇所は、覆う範囲のセル全部に同じ値が
繰り返してある。脚注の参照 `[1]` はセルの中に残り、脚注本文は表の直後にある。

**` ```text ` で囲まれた固定幅ブロック** — PDF 由来（無印）。表・図・コンソール出力が
版面どおりに囲ってあり、**囲みの中は行と桁の位置に意味がある。** 諸元表なら、見出し行の
機種名（`IX2215` 等）と値が桁で対応している。列を数え違えると別機種の値を答えることになるので、
**機種名の桁位置を確かめてから値を読む。**

無印の機能説明書は全機種をまとめたものなので、**どの列を読むかは機種名で決まる。**
`ch01-機能概要/諸元.md` の諸元表は見出しが
`分類  項目  IX2106  IX2207  IX2215  IX2235  IX2310  IX3315  default  制限値` の形で、機種ごとに 1 列ある。
ただし表によって載る機種は違う（`IX2107` は本文には出てくるが、諸元表には列が無い）。
`ch01-機能概要/ハードウェア仕様.md` は見出しが複数行に折り返しており、`-Z` 付き（`IX2215-Z`）は
2 行目に置かれて**上の行の機種と同じ列**を使う。機種条件は表の外にも
`IGMP スヌーピング（IX2215 のみ）` や `※1 IX2215/IX2207/IX2107/IX2106` の形で本文・脚注に出る。

機種名は系列と同じくインベントリの `model` か会話から取る（綴りは見出しと同じ `IX2215` / `IX-R2530`）。
**機種が分からないとき、また表にその機種の列が無いときは推測しない。** ユーザーに機種を尋ねるか、
`ix-show` で `show version` を実行して確認してもらう。
機種が絞れないまま答えるなら、**どの機種の値かを明記する**（「IX2215 では 64、IX3315 では 128」）。
なお `model` で決まるのは諸元値や機種依存の記述だけで、**インタフェース名は決まらない**（後述）。

各ブロックの直後に出所が置いてある。PDF 由来は `<sup>[元 PDF pNNN](...)</sup>`、
Web 由来は `<sup>[出典](https://…#…)</sup>`。

### 4. 図について — ここが最も間違えやすい

**図の中身はテキストだけでは完結しない。** 図のラベル（機器名・インタフェース名・
プロトコル名）は抽出できているが、**矢印の向き・包含関係・順序は失われている。**

```text
マルチキャストサーバ（放送局）        受信端末
upstream                     downstream
IX2000/IX3000     ストリーム      PIM ルータ
```

この断片から「どちらからどちらへ流れるか」は**決まらない**。
**囲みの中の語が読めることと、図が読めていることは別である。**

構成・経路・パケットの流れ・接続関係を問われたら、**囲みのテキストから推測しない。**
出所の行を見て、次のどれかに進む。

**Web 由来（IX-R）— `[図]` がある場合。** 出所がこの形になっている:

```
<sup>[図](../figures/1_loop-guard.svg) / [出典](https://…/02_router/04-1_loop-guard.html#id2)</sup>
```

図は SVG のまま `figures/` に置いてある。**画像として開ける手段があればそれで見る。** 無ければ
SVG は XML なので、テキストとして開いて `<rect>`（箱）の座標と `<path>`（矢印）を読めば
「どの箱からどの箱へ」は辿れる。ラベルは `<text>` にある。図の直前の ` ```text ` の囲みは
その `<text>` を並べたもので、節を探し当てる手がかりであって図の説明ではない。

**PDF 由来（無印）— `[ページ画像]` がある場合。** 出所がこの形になっている:

```
<sup>[元 PDF p1057](../../../FD-ver10.11-1.1.pdf#page=1057) / [ページ画像](../figures/p-1057.png)</sup>
```

`[ページ画像]` のパスを**画像として開き**（`Read` / `view_image` など）、**描かれた図そのものを見て答える。**
リンクは本文ファイルからの相対パスなので、`../` を `<manuals>/ix/fd/` に読み替える。

**ファイル名はリンクに書かれている綴りをそのまま使う。ページ番号から組み立てない。**
桁数とハイフンは焼き方で変わり（`p-1057.png` / `p-001057.png` / `p1057.png`）、
組み立てるとほぼ確実に存在しないパスになる。開けなかったら名前を推測して再試行せず、
`<manuals>/ix/fd/figures/*1057*` を一覧して実在する綴りを確かめる。

囲みのテキストは捨てない。**画像で向きと包含を取り、囲みで語の綴りを取る。**
画像は縮小されて渡るので、細かいラベルが読めなければそう言う。読めたふりをしない。

**PDF 由来でページ画像が無い場合** — 出所が `<sup>[元 PDF pNNN](...)</sup>` だけのとき。
`figures/` が用意されていないか、そのページが焼かれていない。このときは
**断片から構成を組み立てず**、`元 PDF pNNN` を示して「この図は版面を見ないと向きが
分からない」と伝える。ページ画像を用意する方法は `<manuals>/ix/fd/README.md` に書いてある。

## 系列間の差分 (diff.tsv)

`<manuals>/ix-r/diff.tsv` は無印と IX-R のコマンドの対応表（`manualbook diff` が両系列の変換結果から
作る）。無印の設定を IX-R に移すとき、無印で覚えたコマンドが IX-R に無いときに引く。
`kind / ix / ix-r / source / ref_ix / ref_ixr / note` のタブ区切り。

| `kind` | 意味 |
|---|---|
| `renamed` | 名前が変わった（`show logging` → `show syslog`） |
| `moved` | 登録するモードが変わった（`ip dhcp enable`: グローバル → インタフェース） |
| `removed` | 廃止された（`logging packet`）。`ix-r` 列は空で、統一先があれば `note` に書いてある |
| `range` | デフォルト値・設定範囲が変わった（`ip max-route`: `unlimited` 廃止） |
| `changed` | パラメータ・オプションが変わった（`ipsec policy`: `DIRECTION` 削除） |
| `limit` | 対応していた機能が非対応になった（OSPFv2 の仮想リンク） |
| `absent` | 機能の族ごと無い（`ip pim *`: マルチキャスト）。`ix` 列は「先頭の語 `*`」の形 |

**`source` 列で確度が違う。**

- `ch8` — IX-R 機能説明書 8 章「IXシリーズとの差分」の表の書き起こし。一次情報。`ref_ixr` が出典で、
  `ref_ix` は無印コマンドリファレンスの該当項目（引けなかった行は空）。
- `derived` — 無印と IX-R の制限事項を両方読んで導いた差（5 行）。`ref_ix` と `ref_ixr` の両方が出典。
  版の組（無印 10.11 × IX-R 1.5a）で導いたもので、版が上がっていたら出典を読み直す。
- `setdiff` — 両索引の集合差から機械的に出したもの。**目安。** 個々のコマンドが本当に無いかは
  `commands.tsv` で確かめてから答える。

`ref_ix` / `ref_ixr` は `crm:` か `fd:` に続けて各冊子の `source` 列と同じ形（`crm:p765`、
`fd:00_main/13_command_diff.html#id10`）。冊子のディレクトリを選んで、`source` 列と同じ要領で辿る。

```
Grep: pattern="\tshow logging\t" path="<manuals>/ix-r/diff.tsv"      # コマンド名で
Grep: pattern="\tip pim " path="<manuals>/ix-r/diff.tsv"               # 族で（absent 行は「ip pim *」）
```

コマンドの先頭の語で引き、当たった行の `kind` と `source` を添えて答える。当たらなければ
「差分表に無い」と言い、両系列の `commands.tsv` を引いて有無を確かめる（差分表に無い＝同じ、ではない。
8 章は「比較的使用頻度の高い」差分だけを載せている）。

## 報告のしかた

コマンド 1 つにつき、最低限これを示す:

```
系列     : IX-R/IX-V 1.5a
コマンド : ngn ip enable
実行モード: インタフェースコンフィグモード（Ether 系インタフェース）
ユーザー権限: Administrator
説明     : 該当インタフェースを NGN 網とのユーザ網インタフェース（UNI）に設定し、NGN 機能を有効化します。
デフォルト: 無効
出典     : NGN (cli/interface/cli_ngn.html#ngn-ip-enable)
```

出典は本文には書かれていない。節名は `file` 列のファイル名、位置は `source` 列から取る。
`source` は元資料上の位置で、**PDF 由来なら物理ページ（`p61`）、Web 由来なら元のページと
節のアンカー（`cli/…html#…`）。** PDF の `p61` はそのまま PDF ビューアのページ指定に使える
（版面に刷られた `3-29` のような番号は章ごとに振り直されていて使えないので、索引には無い）。
Web のアンカーは冊子の `README.md` にある URL に続ければそのページが開く。

**ノートに制約が書かれていれば必ず伝える**（「複数のインタフェースに設定することはできません」等）。
これを落とすと、設定投入時に初めて弾かれることになる。

## 他の skill との関係

- `ix-configure` で設定を投入する前に、このスキルで**系列を決め、入力形式と実行モードを確認する**。
  特に `no` 形の綴りと、そのコマンドがどのコンフィグモードに属するかを確かめる。
  無印の設定を IX-R に流用するときは `diff.tsv` も引く。
- `ix-show` で出力の読み方が分からないときも、該当コマンドの説明をここで引く。
- ただし**インタフェース名（`GigaEthernet0.0` 等）はマニュアルでは決まらない**。
  機種・構成で異なるので、必ず `ix-show` の `show interfaces` で実機を確認すること。

## 注意事項

- マニュアルは特定の版のもの（各冊子の `README.md` に書いてある）。実機のバージョンが違えば
  差異がありうる。`ix-show` の `show version` と突き合わせ、食い違う可能性があるときはその旨を添える。
- 変換された Markdown は元資料の著作物であり、手元での参照用。外部に転記・配布しない。
