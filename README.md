# pdfbook

PDF のマニュアルを、構造を保った Markdown に変換するツール。

**テキスト層のある PDF に OCR は要らない。** ヘッダ・フッタと段組みさえ処理できれば、
本文はそのまま取り出せる。852 ページのコマンドリファレンスが 8 秒で変換できる。

```
pdfbook fetch   マニフェストに書いた PDF をまとめて取得する (SHA256 検証つき)
pdfbook probe   PDF を試し読みして段組み・ヘッダ位置を自動較正し、プロファイルを作る
pdfbook md      テキスト層のある PDF を構造つき Markdown に変換する
pdfbook scan    見開きスキャン画像を 1 ページずつに分割する (テキスト層が無い場合)
```

## 必要なもの

- Go 1.25 以降（ビルド用）
- `pdftotext`（[Xpdf](https://www.xpdfreader.com/) または poppler-utils）が PATH にあること

```console
$ go build -o pdfbook .
$ pdftotext -v          # 4.x 系で動作確認
```

## 使い方

```console
$ pdfbook fetch -manifest manifest.json -out pdf/
$ pdfbook probe pdf/CRM-ver10.11-1.1.pdf -out profiles/nec-ix-crm.json
$ pdfbook md    pdf/CRM-ver10.11-1.1.pdf -profile profiles/nec-ix-crm.json -out out/crm
```

出力は次の形になる。1 冊を 1 ファイルにすると引けないので、節ごとに分ける。

```
out/crm/
├── index.md          コマンド索引 (コマンド名 → 該当箇所) と目次
├── commands.tsv      command / entry / file / anchor / page のタブ区切り索引
├── README.md         生成条件と出典
└── ch03-インタフェース編/
    └── NGN.md        本文
```

## 仕組み

### なぜ OCR が要らないのか

紙をスキャンした PDF でなければ、PDF には文字がそのまま入っている。読めないように
見えるのはたいてい取り出し方の問題で、この資料の場合は `pdftotext` の出力エンコーディングが
既定で Latin-1 だったために日本語が消えていただけだった（`-enc UTF-8` で解決する）。

残る難所は次の 3 つで、いずれも座標計算なしに `pdftotext` のマージン指定だけで扱える。
`-marginl/-marginr/-margint/-marginb` は、指定した端から N ポイント以内のテキストを捨てる。

| 欲しいもの | 指定 |
|---|---|
| 左カラムだけ | `-marginr <ガター左端>` |
| 右カラムだけ | `-marginl <ガター右端>` |
| 柱（ヘッダ）だけ | `-marginb <ヘッダのすぐ下>` |
| ノンブル（フッタ）だけ | `-margint <フッタのすぐ上>` |
| 本文だけ | `-margint <天> -marginb <地>` |

1 冊あたり 5 回の `pdftotext` 起動で読み切れる（ページごとに呼んではいけない。
ページ境界は出力中の改ページ `\f` で分かる）。

### 較正は目視ではなく不変条件で

`probe` はページ寸法もガター位置も、`pdftotext` を走らせて**文字数を数える**だけで決める。
PDF の内部構造（MediaBox、フォント、CMap）は一切パースしないので、CJK の CMap 対応で
崩れることがない。

段組みの判定基準は次の等式である。

```
左カラムの文字数 + 右カラムの文字数 == ページ全体の文字数
```

これが崩れるのは「どちらの段にも入らない文字がある」（ガターが広すぎる）か
「両方に入る文字がある」（狭すぎる）ときだけ。ガターが 4pt ずれていても目視では
気づけないが、この数値は必ず反応する。同点になる切れ目が並んだ範囲が段間の空白
そのものなので、その中央を採る。

同じ等式を変換時にもページごとに使い、崩れるページ（目次のリーダ罫、段抜きの図表）は
全幅として読む。ただし完全一致は求めない。段間にわずかに掛かった数文字のせいで本文
ページが全幅と誤判定されると、左右の段が 1 行に混ざってページごと壊れるためである。
実測では本文ページのずれは高々十数文字、目次は 130 文字前後で、あいだに大きな隔たりがある。

**この許容は無損失ではない。** ずれのあるページ（852 ページ中 63 ページ）では、段間に
掛かった数文字が落ちるか二重になる。ページ全体が壊れるより桁違いにましだという判断で
あって、1 文字も違わないことを保証してはいない。

### 構造は版面から取る

目次を解析しなくても、版面そのものが構造を持っている。

- **柱（ヘッダ）** = 節名
- **ノンブル（フッタ）** = 印刷ページ番号（`3-29`）。前半がそのまま章番号になる
- **章扉**（ノンブルが `N-1`）の大見出し = 章名
- **`■`** = コマンド項目の始まり
- **見出し語**（入力形式 / パラメータ / 説明 / …）= 項目内のフィールド

項目が段やページをまたいでも、読み順（左段 → 右段 → 次ページ）に並べた 1 本の行列を
`■` で切るだけなので、自然に繋がる。

### 日本語の折り返しを畳む

版面の折り返しをそのまま残すと、行末で単語が割れて（「最大レ」+「コード数」）grep が
当たらなくなる。逆に英字どうしは空白で繋がないと単語がくっつく。前の行が句点で終わって
いなければ次の行を繋ぎ、両端が半角英数のときだけ空白を挟む。

コマンド構文（入力形式・入力例）は版面どおりに残す。索引を作るときだけ折り返しを繋ぎ直す。

## 他の資料に使う

`probe` が作るプロファイルの `entryMarker` と `fieldLabels` を、その資料の書式に合わせる。
段組み・ページ寸法・柱の位置は `probe` が自動で決める。

```json
{
  "entryMarker": "■",
  "fieldLabels": ["入力形式", "パラメータ", "説明", "..."]
}
```

`probe` がテキスト層をほとんど検出できなかった場合は紙スキャン由来の画像 PDF なので、
`md` は使えない。画像化して `pdfbook scan` で見開きを分割し、OCR に回す経路になる。

## 生成物は配布しない

変換した Markdown は元の PDF の著作物であり、再配布にあたる。`out/` と `*.pdf` は
`.gitignore` で除外してある。マニュアルが必要な人は、それぞれの手元で `fetch` → `md` を実行する。
